# Конкурентный поисковый Telegram-бот на aiogram 3

Telegram-бот, который по одному сообщению пользователя ищет информацию сразу в трёх независимых источниках: **Wikipedia, GitHub и Stack Overflow**. Бот объединяет найденное в один ответ и сообщает, если какой-либо источник оказался недоступен.

Идея проекта появилась из интереса к **`asyncio` и конкурентному выполнению I/O-bound задач**. Захотелось на практике проверить, как одновременное обращение к нескольким внешним API влияет на время поиска, и разобраться с таймаутами, обработкой ошибок и ограничением конкурентности.

## Как работает бот

1. Пользователь отправляет текстовый запрос в Telegram, например `python asyncio`.
2. Обработчик передаёт запрос в `general_search()`.
3. Поисковый сервис запускает провайдеры Wikipedia, GitHub и Stack Overflow конкурентно.
4. Каждый провайдер обращается к своему API и преобразует ответ в единую модель результатов.
5. Сервис объединяет успешные результаты и отдельно сохраняет названия источников, завершившихся с ошибкой.
6. Функция форматирования формирует сообщение, которое отправляется пользователю.

```text
Пользователь Telegram
        ↓
      Handler
        ↓
  general_search()
        ↓
  ┌─────┼───────────┐
  ↓     ↓           ↓
Wiki GitHub Stack Overflow
  └─────┼───────────┘
        ↓
SearchResult + broken_providers
        ↓
     Formatter
        ↓
  Ответ в Telegram
```

### Что возвращают источники

- **Wikipedia** — название статьи, краткое описание, ссылка.
- **GitHub** — полное имя репозитория (`owner/repository`), описание, основной язык, количество звёзд и ссылка.
- **Stack Overflow** — название вопроса, ссылка, количество ответов, рейтинг и наличие принятого ответа.

Результаты представлены объектами на основе `SearchResult` с общими полями `title`, `description`, `url` и `source`. Специфичные поля GitHub и Stack Overflow хранятся в соответствующих моделях. Telegram-обработчик не разбирает JSON внешних API: этим занимаются провайдеры.

## Конкурентность и обработка ошибок

В проекте применяются:

- `asyncio.gather(..., return_exceptions=True)` — конкурентный запуск независимых провайдеров без потери результатов остальных при ошибке одного источника.
- `asyncio.wait_for(..., timeout=5)` — ограничение времени ожидания каждого запуска провайдера.
- Общий `asyncio.Semaphore(6)` — ограничение количества одновременно выполняющихся операций с провайдерами при нескольких пользовательских запросах.
- Проверка HTTP-статусов — ошибки внешних API не маскируются под пустую выдачу.
- Раздельная обработка `results` и `broken_providers` — пользователь видит найденные данные даже при частичном отказе источников.

Пустой успешный поиск и ошибка API — разные ситуации. Если результатов нет, бот сообщает об отсутствии находок; если провайдеры завершились с ошибками, дополнительно перечисляет недоступные источники.

Для проверки ограничения конкурентности запускались три поиска одновременно — потенциально девять операций провайдеров. Диагностический счётчик подтвердил, что при `Semaphore(6)` одновременно выполнялось не более шести таких операций.

## Эксперимент: последовательный и конкурентный поиск

Чтобы оценить пользу `asyncio` для сетевых задач, были проведены замеры времени работы с **одинаковым запросом `python asyncio`** и теми же тремя внешними API.

- **Последовательный вариант:** каждый следующий провайдер запускается после завершения предыдущего.
- **Конкурентный вариант:** три провайдера запускаются через `asyncio.gather()`, поэтому ожидания их HTTP-ответов могут перекрываться.

Время измерялось с помощью `time.perf_counter()`. Последовательный и конкурентный варианты запускались по очереди, а не одновременно.

| Запуск | Последовательно | Конкурентно |
|:---:|---:|---:|
| 1 | 2,789 с | 1,037 с |
| 2 | 2,542 с | 1,085 с |
| 3 | 3,696 с | 1,062 с |
| **Среднее** | **3,009 с** | **1,061 с** |

**Результат:** в этой серии измерений конкурентный поиск оказался приблизительно **в 2,84 раза быстрее**.

Это результат конкретного эксперимента, а не универсальное ускорение от `asyncio`. Время зависит от сети, нагрузки внешних сервисов и их ограничений. При одном из более ранних запусков GitHub вернул HTTP 403; такой запуск не использовался для сравнения успешного выполнения всех трёх провайдеров.

Эксперимент воспроизводится отдельным скриптом `bot/bench.py`, не требуя изменений рабочей логики поиска.

## Установка и запуск

Для запуска необходимы **Python 3.12**, доступ к интернету и токен Telegram-бота от [@BotFather](https://t.me/BotFather).

1. Склонируйте репозиторий и перейдите в папку проекта:

   ```bash
   git clone https://github.com/this0is0the0way/aibot.git
   cd aibot
   ```

2. Создайте и активируйте виртуальное окружение (Linux / WSL):

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

3. Установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Создайте файл `.env` в корне проекта и укажите в нём токен:

   ```dotenv
   BOT_TOKEN=ваш_токен_бота
   ```

   Не добавляйте `.env` с настоящим токеном в Git.

5. Запустите бота из корня проекта:

   ```bash
   python -m bot
   ```

6. Откройте своего бота в Telegram и отправьте поисковый запрос.

**Зависимости:** `aiogram`, `httpx`, а при использовании `load_dotenv()` — также `python-dotenv`. Убедитесь, что все непосредственно используемые сторонние пакеты перечислены в `requirements.txt`.

### Запуск бенчмарка

Из корня проекта:

```bash
python -m bot.bench
```

Скрипт обращается к реальным внешним API, поэтому результаты могут отличаться между запусками. Ошибки источников, например HTTP 403 при превышении лимитов, следует учитывать при интерпретации замеров.

## Что удалось изучить

В процессе разработки были применены асинхронные HTTP-запросы, `await`, `asyncio.gather()`, таймауты, `Semaphore`, изоляция ошибок отдельных задач, нормализация ответов разных API и разделение ответственности между обработчиком, поисковым сервисом, провайдерами и форматированием.

**Главный вывод:** конкурентное выполнение особенно полезно в I/O-bound задачах, когда значительная часть времени уходит не на вычисления, а на ожидание внешних систем.

## Используемые технологии

- Python 3.12
- aiogram 3

- asyncio

- GitHub REST API
